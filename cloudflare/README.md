# Traider Cloudflare — demo accounts on the free tier

> Branch context: this directory lives on branch `cloudflare-agents` of
> github.com/iyeque/traider (created from master 23c50ff). The Python bot stays
> on `master`. See COMPARISON_TO_MASTER.md for feature parity and deviations.

TypeScript port of the [Traider](https://github.com/iyeque/traider) Python bot's
strategy core, running as Cloudflare Agents / Durable Objects. Each demo account
is one Durable Object with its own SQLite ledger, ticking every 60 seconds
against **live Binance public market data** — no API keys, no real orders.

This is Option 1 from the planning conversation: port the trading logic to
TypeScript so everything stays on the Workers Free plan.

## Architecture

```
React dashboard (useAgent WebSocket, real-time state sync)
  |
Worker (src/index.ts) — routeAgentRequest /agents/trading-account/:name
  |
TradingAccount Durable Object (src/account.ts), one per demo account
  ├── SQLite (this.sql): full trade log
  ├── State API (setState): balance/equity/positions/trades synced to clients
  ├── scheduleEvery(60, "tick"): durable recurring strategy cycle
  └── tick(): klines -> indicators -> safety gate -> regime -> strategy -> sim fills
```

- `src/core/indicators.ts` — RSI, MACD, ATR, Bollinger (exact pandas/ta semantics)
- `src/core/strategy.ts` — generate_signal, regime selection, trade sizing,
  breakout SL/TP, grid ladder, safety gate
- `src/core/sim.ts` — demo fill model, PnL, exit checks, drawdown guard
- `src/market.ts` — Binance public klines/ticker via data-api.binance.vision (keyless)
- `src/sentiment.ts` — CryptoPanic -> NewsAPI -> RSS -> Fear & Greed aggregation
- `dashboard/` — React 19 + agents/react useAgent; account tabs, equity sparkline,
  positions/trades tables, pause/resume/tick/reset/config controls

## Fidelity to the Python bot (verified, not claimed)

`tests/fixtures/python_fidelity.json` is generated by running the **real Python
functions** (`bot/strategy.py`, `bot/trading.py` with pandas + ta) on 120
synthetic candles. The vitest suite asserts the TS port matches element-wise
(1e-9): RSI/MACD/ATR/Bollinger arrays, 108 generate_signal cases, trade-sizing
cases. Preserved quirks:

- RSI uses a simple rolling mean of gains/losses (NOT Wilder's), with the pandas
  `delta.where` leading-zero behavior (first valid value at index period-1).
- Bollinger `window_dev` is cast to int (Python passes `int(window_dev)` to ta),
  so dev=1.5 behaves as dev=1. Population std (ddof=0), matching ta.
- `is_market_safe` logs low Fear & Greed but STILL ALLOWS trading (the Python
  `return False` is commented out "for testing purposes"). Ported as-is.
- Grid sizing ignores sentiment (Python passes 0).

Documented deviations (demo mode):

- Headline scoring uses AFINN-165 (`sentiment` npm) instead of TextBlob — no JS
  port of TextBlob exists. Same [-1,1] shape, different lexicon.
- With no sentiment API keys, sentiment falls back to a Fear & Greed proxy
  `(fng-50)/50` so demo accounts can trade; disable with DEMO_PROXY_SENTIMENT="false".
  At the default threshold (0.0) extreme-fear markets block entries — faithful
  to the Python safety gate. Lower `sentimentThresholdPositive` in the dashboard
  to watch entries in bearish conditions.
- Fills are simulated: market orders at last price +/- slippage
  (0.05% + qty*1e-6), fee 0.1% (config.py BACKTEST_* defaults). Resting grid
  buys fill when the candle low trades through the level; exits check the latest
  candle (stop assumed first if both SL and TP are in range). The full
  backtest.py engine (walk-forward, latency sim) is a follow-up port.
- Breakout 'sell' signals open simulated short positions with 1:1 notional
  reservation (the Python bot's PositionManager flips PnL sign for sells).
  Live spot cannot short without margin — flagged for the live-mode port.

## Market data on deployed Workers (verified 2026-11-23)

`data-api.binance.vision` works from a normal network but returns **HTTP 403
from Cloudflare Workers egress** (datacenter IP range). `src/market.ts` falls
back automatically: Binance → Coinbase Exchange public OHLC → Kraken public
OHLC (all keyless). Coinbase returns numeric epoch **seconds** in `candles`
(not ISO strings); Kraken canonicalizes pair names (XBTUSD → XXBTZUSD), so the
adapter finds the candles key instead of hard-coding it. Adapters are covered
by `tests/market.test.ts`.

Live deployed tick: regime=sideways (real ATR), sentiment≈0.0017 (real NewsAPI
headlines), Fear & Greed=11, lastError=null. URL:
https://traider-cloudflare.mmmaximus18.workers.dev

## Per-token tuning (Phase 1 — backtest -> DO config)

`backtest/run_per_symbol.py` (on this branch) runs the exact 18-parameter
Optuna search space from `backtest/optimize_params.py` through the REAL
`backtest/strategy_backtest()` over the checked-in hourly CSVs plus
`data_acquisition/historical_sentiment.csv`, once per token, and writes
`cloudflare/src/tuned_params.json`. `src/tunedParams.ts` maps the snake_case
output onto StrategyConfig; `TradingAccount.onStart` merges it per symbol, and
a `configTuned` marker migrates existing Durable Objects on their next wake.

First pass (real output): 8 Optuna trials per symbol on a shared 407-candle
window 2025-06-28 -> 2025-07-14, sentiment fully overlapping. Starting $10,000:
BTC $10002.66 / 2 trades, ETH $10030.08 / 14, SOL $10000.37 / 10,
BNB $10009.70 / 8. Verified live: all four deployed accounts report
`configTuned=true` with their own ATR period, grid levels, risk % and BB flags.

CAVEAT: in-sample, only 8 trials, ~17 days of 2025 data; gains are noise-level
and NOT walk-forward validated. Backtesting/Optuna itself stays in Python —
it was not ported to the Worker. Re-run before trusting:
`python3 backtest/run_per_symbol.py --trials 100 --start ... --end ... --out cloudflare/src/tuned_params.json`

## Phase 1b — tuning workflow (GitHub Action)

`.github/workflows/tune.yml` lives on this branch and runs via
`workflow_dispatch` (GitHub only runs `schedule:` workflows on the DEFAULT
branch, which here is the stale `main`). Dispatch from the Actions UI or:

```
GITHUB_TOKEN=... ./scripts/dispatch_tune.sh 50 0.25
```

Four parallel matrix jobs (one per token) run `backtest/run_per_symbol.py`
with a train/out-of-sample split. The tuner uses checked-in CSVs and an
OfflineClient for exchange filters — **no Binance network calls from GitHub
runners**, whose shared IPs can be WAF-blocked (403). Optuna sees only the
training slice; the held-out tail decides promotion.

Guardrails (all four tokens must pass): out-of-sample return > 0, at least 3
OOS trades, profit factor > 1.2, win rate >= 45%, max drawdown < 20%.
The aggregate job writes a job summary, and opens a PR against
`cloudflare-agents` only when all pass; otherwise it reports "no promotion"
and leaves `tuned_params.json` untouched. Promotion requires a merge and then
`npm run deploy` — params are baked into the Worker at build time.

Suggested cadence: daily data refresh on a clean-IP machine (commit CSVs),
weekly dispatch of this workflow, monthly deeper walk-forward, manual
re-dispatch on regime breaks. Verified locally: YAML parses, both merge paths
(promote/no-promote) produce correct outputs, OOS split + guardrails work.

### Daily data refresh (second half of Phase 1b)

`backtest/refresh_data.py` fetches a rolling 1,000 x 1h OHLCV window for all
four symbols from the keyless `data-api.binance.vision` endpoint (works from
this WSL machine; 403 from Cloudflare/GitHub runners) and merges fresh hourly
sentiment from NewsAPI + RSS into the existing CSV. CryptoPanic is skipped
(HTTP 403), and the upstream module's URL logging is suppressed so the API
key can never reach cron logs. Run with `--commit` to overwrite the CSVs and
push them to cloudflare-agents.

Installed in this machine's crontab at 04:30 local (00:30 UTC) daily under the
marker `# traider-daily-refresh`, logging to the Hermes scratch directory.
Verified live: all four CSVs now cover 2026-10-17 -> 2026-11-27, sentiment
extends to 2026-11-27 (748 rows), the tuner reads the refreshed data correctly,
and the commit/push path works. NewsAPI currently returns 429 on the free
tier, so the job falls back to RSS headlines; that is deliberate and safe.

This also supplies repository activity well inside the 60-day window that can
auto-disable scheduled workflows in public repos.

### Phase 2 execution plane (Vercel)

Binance's WAF blocks signed order requests from Cloudflare egress, but signed
reads work. The Worker therefore keeps the strategy, state and keys, and signs
short-lived order intents; a Vercel function pinned to `bom1` (Mumbai) posts
them from an accepted egress. Vercel never sees the API secret. Secrets:
`EXECUTOR_TOKEN` (Worker + Vercel), `VERCEL_EXECUTOR_URL` (Worker),
`ENABLE_TESTNET_ORDERS` (kill switch; currently TRUE for live observation —
set to false to disarm). When a breakout signal fires in testnet mode the DO
places a real market order plus OCO exits through Vercel; demo mode is unchanged. Verified with real 0.0001
BTC testnet BUY/SELL orders filled end-to-end through Worker → Vercel → Binance.

### Multi-source sentiment (2026-11-28)

Headline sentiment now aggregates CryptoPanic (if key), NewsAPI (if key),
GDELT DOC 2.0 (keyless, cached 5 min, proxied via Vercel if Cloudflare egress
is blocked), and six RSS feeds. Headlines are deduplicated and each source is
AFINN-scored and weighted; the live state exposes `sentimentSources`,
`sentimentBySource` and `sentimentStale`. Fear & Greed remains a separate
input. The historical refresh script uses the same source set.

IMPORTANT: this changes the sentiment distribution, so the tuned threshold
(0.10) no longer corresponds to the old data. Testnet orders were disarmed
while this is validated; re-run Optuna (Phase 1c) before re-arming.

## Operating cadence (what actually runs)

| Layer | Frequency | Detail |
| --- | --- | --- |
| Live strategy (each Durable Object) | Every 60 seconds | `scheduleEvery(60, "tick")`: fetch klines + sentiment, compute indicators, safety gate, signals. In testnet mode entries/exits go through Vercel; demo mode simulates. |
| Market data for tuning | Daily, 00:30 UTC (04:30 local +04) | WSL cron `# traider-daily-refresh` runs `backtest/refresh_data.py --commit`: rolling 1,000 x 1h candles for four tokens plus merged hourly sentiment; commits CSVs to `cloudflare-agents`. |
| Backtest / Optuna tuning | Every other Sunday, 02:30 UTC | `schedule: "30 2 * * 0"` plus epoch-week parity gate on the default `master` workflow; jobs check out `cloudflare-agents`. 50 Optuna trials per token, 25% out-of-sample holdout. First live scheduled run 2026-12-06. `workflow_dispatch` always runs and ignores parity. |
| Promotion | Only after a passing bi-weekly run | Guardrails: OOS return > 0, >= 3 OOS trades, profit factor > 1.2, win rate >= 45%, max drawdown < 20%. A PR opens only if all four tokens pass; merge + redeploy is required because params are baked into the Worker at build time. |
| Live sentiment gate | Every tick (60 s) | NewsAPI/RSS headlines + Fear & Greed; NewsAPI free tier currently 429, so RSS fallback is used. Historical sentiment CSV is refreshed daily for backtests. |

Not automated yet: deeper monthly walk-forward validation. Public repos can auto-disable scheduled workflows after 60 days of inactivity; the daily data commits keep activity inside that window.

## Free tier fit (verified against Cloudflare docs, Nov 2026)

- Workers Free: 100,000 requests/day, 10 ms CPU per invocation, 128 MB memory,
  50 subrequests/request. A tick is ~4 subrequests and well under 10 ms CPU
  (indicator math over 100 candles is sub-millisecond; fetch wait time does not
  count as CPU).
- SQLite Durable Objects on Free: 100 classes, 5 GB storage/account, 1 GB/object.
- 60 s polling = 1,440 ticks/day/account -> ~69 accounts at the 100k request
  ceiling (dashboard WebSocket messages also count). Four demo accounts use
  ~5,760 requests/day — comfortable headroom.
- Idle objects hibernate; schedules persist in SQLite and survive eviction.

## Deploy

```bash
npx wrangler login    # OAuth in your browser — NO account ID needed manually
npm run deploy        # vite build + wrangler deploy
```

`wrangler login` authorizes via Cloudflare's OAuth flow; the account is picked
from your account list (if you have several) or set `CLOUDFLARE_ACCOUNT_ID` in
the environment. No local wrangler account config exists on this machine yet.

Sentiment API key status (verified 2026-11-20 from the Python bot's .env):
- NEWSAPI_KEY: HTTP 200, 10 articles returned — WORKING. Set it as a secret.
- CRYPTOPANIC_API_KEY: HTTP 403 (Cloudflare bot challenge on v1/posts) — NOT
  usable from here; the port skips it and uses NewsAPI + RSS + Fear & Greed.

Optional secret (real headline sentiment instead of the F&G proxy):

```bash
npx wrangler secret put NEWSAPI_KEY
```
