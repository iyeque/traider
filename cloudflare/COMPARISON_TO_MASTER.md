# cloudflare-agents vs master — comparison

Branch `cloudflare-agents` was created from `master` at commit `23c50ff`
("feat: Enhance trading bot with async functionality and improved
configuration"). The Python bot remains on `master`; this branch ADDS the
`cloudflare/` directory and does not modify the Python sources. Note: the
uncommitted WIP on master (main.py, config.py, fetch_live_sentiment.py) is NOT
in this branch — regenerate `cloudflare/tests/fixtures/python_fidelity.json`
from the real Python functions if those changes are committed and affect
strategy semantics.

## 1. Runtime & deployment

| | master (Python bot) | cloudflare-agents (this branch) |
|---|---|---|
| Runtime | Python 3 / asyncio, local or Docker Compose | Cloudflare Workers + Durable Objects (Agents SDK 0.34) |
| Deployment | `python main.py` / `docker-compose up -d` | `npx wrangler login` then `npm run deploy` (free tier) |
| Scheduling | `asyncio.sleep(TRADE_INTERVAL_SECONDS)` loop | `scheduleEvery(60, "tick")` — durable alarm in the DO's SQLite |
| Accounts | one process, one symbol from `.env` | one Durable Object per demo account (btc/eth/sol/bnb-demo), independent balance/ledger |
| State | CSV logs + in-memory singletons | SQLite `trades` table (full log) + State API (client-synced recent window) |
| Dashboard | embedded aiohttp + WebSocket on :8181 | React 19 + `useAgent` WebSocket, served as Worker assets |
| Dependencies | `requirements.txt` (binance, ta, optuna, etc.) | `npm install --legacy-peer-deps` (agents, react, pinned MCP client peer) |

## 3. Feature parity

Ported and verified:
- All indicators, `generate_signal` (108 truth-table cases from the real
  Python function), ATR regime selection, trade sizing, breakout SL/TP, grid
  ladder + invalidation, safety gate, realized/unrealized PnL, drawdown guard.
- Sentiment aggregation order: CryptoPanic -> NewsAPI -> RSS -> Fear & Greed.
- Multi-account dashboard with live state sync and pause/resume/tick/reset/config.

Not ported (stays on master):
- Real signed order execution (live/testnet Binance client, OCO orders,
  MIN_NOTIONAL/LOT_SIZE formatting, order-monitor polling of `get_my_trades`).
- `backtest/` engine (latency simulation, walk-forward Optuna optimization,
  comprehensive metrics) and `advice.md` growth roadmap.
- CSV trade logs (replaced by SQLite), NLTK/TextBlob stack, on-chain/ML ideas.

Preserved quirks (deliberate, with comments):
- RSI = simple rolling mean of gains/losses with `delta.where`'s leading zero.
- Bollinger `window_dev` int-cast (1.5 -> 1); population std (ddof=0, as ta does).
- Low Fear & Greed logs a warning but ALLOWS trading (Python's `return False`
  is commented out); bearish sentiment still blocks entries.
- Grid sizing ignores sentiment (Python passes 0).

Documented deviations:
- AFINN-165 static lexicon replaces TextBlob (no JS port); bundled as JSON
  because the npm `sentiment` package's dynamic `require` cannot be bundled
  into a Worker. Scorer output verified identical to the npm package in Node.
- No API keys needed for demo: market data from keyless
  `data-api.binance.vision` (HTTP 403 from Workers egress — falls back to Coinbase then Kraken public OHLC); with no headline keys, sentiment = (fng-50)/50.
- Fills are simulated (fee 0.1%, slippage 0.05% + qty*1e-6, from config.py
  BACKTEST_* defaults); grid limit buys fill on candle-low crosses; exits
  checked per latest candle, stop assumed first if both SL and TP in range.
- Breakout `sell` opens a simulated short position (1:1 notional reservation);
  live spot shorting would need margin.
- CryptoPanic v1/posts returns HTTP 403 from this host (Cloudflare challenge);
  NewsAPI key from master's .env returns HTTP 200 with 10 articles and is the
  working headline source when configured as `NEWSAPI_KEY` secret.

## Per-token tuning (Phase 1 — backtest -> DO config)

`backtest/run_per_symbol.py` (on this branch) runs the exact 18-parameter
Optuna search space from `backtest/optimize_params.py` through the REAL
`backtest/strategy_backtest()` over the checked-in hourly CSVs plus
`data_acquisition/historical_sentiment.csv`, once per token, and writes
`cloudflare/src/tuned_params.json`. `src/tunedParams.ts` maps the snake_case
output onto StrategyConfig; `TradingAccount.onStart` merges it per symbol, and
a `configTuned` marker migrates existing Durable Objects on their next wake.

First pass (real output): 8 Optuna trials per symbol on a shared 407-candle
window 2025-06-28 -> 2025-07-14, sentiment fully overlapping. Starting $10,000:
BTC $10002.66 / 2 trades, ETH $10030.08 / 14, SOL $10000.37 / 10,
BNB $10009.70 / 8. Verified live: all four deployed accounts report
`configTuned=true` with their own ATR period, grid levels, risk % and BB flags.

CAVEAT: in-sample, only 8 trials, ~17 days of 2025 data; gains are noise-level
and NOT walk-forward validated. Backtesting/Optuna itself stays in Python —
it was not ported to the Worker. Re-run before trusting:
`python3 backtest/run_per_symbol.py --trials 100 --start ... --end ... --out cloudflare/src/tuned_params.json`

Signed Binance testnet execution (Phase 2) is still pending; testnet.binance.vision
was verified reachable (HTTP 200) from the deployed Worker.

## Phase 1b — tuning workflow (GitHub Action)

`.github/workflows/tune.yml` lives on this branch and runs via
`workflow_dispatch` (GitHub only runs `schedule:` workflows on the DEFAULT
branch, which here is the stale `main`). Dispatch from the Actions UI or:

```
GITHUB_TOKEN=... ./scripts/dispatch_tune.sh 50 0.25
```

Four parallel matrix jobs (one per token) run `backtest/run_per_symbol.py`
with a train/out-of-sample split. The tuner uses checked-in CSVs and an
OfflineClient for exchange filters — **no Binance network calls from GitHub
runners**, whose shared IPs can be WAF-blocked (403). Optuna sees only the
training slice; the held-out tail decides promotion.

Guardrails (all four tokens must pass): out-of-sample return > 0, at least 3
OOS trades, profit factor > 1.2, win rate >= 45%, max drawdown < 20%.
The aggregate job writes a job summary, and opens a PR against
`cloudflare-agents` only when all pass; otherwise it reports "no promotion"
and leaves `tuned_params.json` untouched. Promotion requires a merge and then
`npm run deploy` — params are baked into the Worker at build time.

Suggested cadence: daily data refresh on a clean-IP machine (commit CSVs),
weekly dispatch of this workflow, monthly deeper walk-forward, manual
re-dispatch on regime breaks. Verified locally: YAML parses, both merge paths
(promote/no-promote) produce correct outputs, OOS split + guardrails work.

### Phase 1b live verification (2026-11-25)

First GitHub run failed: `*.csv` was gitignored, so the runner checkout had no
`backtest/*_1h.csv` (FileNotFoundError). Fixed by force-adding the five data
files to cloudflare-agents (264 KB total). Second run (2-trial smoke,
`https://github.com/iyeque/traider/actions/runs/45577503929`) succeeded: all
four tune jobs plus aggregate green. Report showed BNB/BTC/ETH passing all
guardrails, SOL failing with only 2 out-of-sample trades, so overall verdict
"NO PROMOTION - existing params kept" and no PR was opened — correct behaviour.

GitHub registers workflows only from the DEFAULT branch (`master`, confirmed
via API). The workflow file is mirrored on master; its jobs explicitly check
out cloudflare-agents. This avoids changing the repo default branch and still
now carries `schedule: 30 2 * * 0` with an epoch-week parity gate for a true 14-day cadence (next live run 2026-12-06); workflow_dispatch ignores the gate.

### Daily data refresh (second half of Phase 1b)

`backtest/refresh_data.py` fetches a rolling 1,000 x 1h OHLCV window for all
four symbols from the keyless `data-api.binance.vision` endpoint (works from
this WSL machine; 403 from Cloudflare/GitHub runners) and merges fresh hourly
sentiment from NewsAPI + RSS into the existing CSV. CryptoPanic is skipped
(HTTP 403), and the upstream module's URL logging is suppressed so the API
key can never reach cron logs. Run with `--commit` to overwrite the CSVs and
push them to cloudflare-agents.

Installed in this machine's crontab at 04:30 local (00:30 UTC) daily under the
marker `# traider-daily-refresh`, logging to the Hermes scratch directory.
Verified live: all four CSVs now cover 2026-10-17 -> 2026-11-27, sentiment
extends to 2026-11-27 (748 rows), the tuner reads the refreshed data correctly,
and the commit/push path works. NewsAPI currently returns 429 on the free
tier, so the job falls back to RSS headlines; that is deliberate and safe.

This also supplies repository activity well inside the 60-day window that can
auto-disable scheduled workflows in public repos.

## 5. Free tier fit (Cloudflare docs, Nov 2026)

- Workers Free: 100k requests/day, 10 ms CPU/invocation (I/O wait excluded),
  128 MB memory, 50 subrequests/request.
- SQLite Durable Objects on Free: 100 classes, 5 GB storage/account, 1 GB/object.
- Four accounts at a 60 s tick = ~5,760 requests/day; ~69 accounts fit the
  100k/day ceiling before dashboard WebSocket traffic.

Deployed Worker: https://traider-cloudflare.mmmaximus18.workers.dev (live tick: regime=sideways, real NewsAPI sentiment≈0.0017, F&G=11, lastError=null). Secrets set: NEWSAPI_KEY (CryptoPanic not needed — HTTP 403).

## 6. How to use both

Python bot (master): `cd Traider && python3 -m unittest discover bot && python3 check_testnet.py`.
Cloudflare port (this branch): `cd Traider/cloudflare && npm install --legacy-peer-deps && npm test && npm run build && npm run dev:worker` (add `npm run dev:dashboard` for the UI). Deploy with `npx wrangler login && npm run deploy`.
